# Журнал решений

Дата: 2026-10-17, часовой пояс пользовательского сеанса Europe/Moscow.
Изменение принятого решения требует новой записи с причиной; историю не переписывать.

| ID | Статус / основание | Решение |
| --- | --- | --- |
| D01 | Подтверждено пользователем | Сейчас только Harness, спецификации и задания; агентов на реализацию не запускать. |
| D02 | Подтверждено пользователем | Harness означает AGENTS.md, карту знаний, спецификации, небольшие задания и автоматические проверки. |
| D03 | Подтверждено пользователем | Простой MVP с очередью в памяти и явными рисками потерь/дублей. |
| D04 | Подтверждено пользователем | Python 3.12, asyncio, Docker Compose; отдельный контейнер рядом с существующим CH. |
| D05 | Подтверждено пользователем | Пользовательский DDL без изменений, TTL и дедупликации; database через env. |
| D06 | Заменено D07 | Изначально выбраны 16 инструментов прототипа. Это больше не действующее требование. |
| D07 | Последнее указание пользователя | Полный список берётся из корневого subscribe_msg.yaml сервиса quotes, а не из прототипа сделок. Снимок содержит 101 пару; меняется только dataType 3 → 2. |
| D08 | Подтверждено пользователем | subscribeType=0 и responseType=LastTrades реально работали для сделок; это сильнее спорного описания PDF. |
| D09 | Неизвестно, пользователь поручил проверить позже | Версия production ClickHouse устанавливается перед deployment. |
| D10 | Проектный baseline | UTC offsets обязательны, миллисекунды индекса усекать, raw JSON сохранять дословно. |
| D11 | Проектный baseline | Trade-shaped LastTradesSuccess поддержать как совместимость с PDF; live capture такого payload пока отсутствует. |
| D12 | Проектный baseline | Bounded shutdown, проверка worker failure и refresh долгой WS-сессии обязательны для приёмки. |
| D13 | Проектный baseline | Миграции применяются отдельно; ingestion не требует DDL-привилегий и не исправляет схему автоматически. |
| D14 | Последующее указание пользователя; заменяет D01 для текущего этапа | Реализовать T01 и T02, затем двигаться по зависимостям задач с проверкой каждого результата. |
| D15 | Повторное поручение пользователя | Для передачи на другой сервер использовать читаемые image tags без digest и локальных сетевых обходов; проверить код, зафиксировать все результаты и подготовить серверный runbook. ClickHouse доступен по IP/DNS и HTTP(S)-порту; секреты задаются только на сервере. |
| D16 | Исправление пользователя в репозитории; уточняет database в D05 | Канонический DDL создаёт `bronze.trades_raw_json`. Defaults, примеры и изолированный integration используют `CLICKHOUSE_DATABASE=bronze`; init проверяет соответствие env и DDL до сети, SQL не переписывается. Остальная схема сохранена. |

Проектные baselines — решения подготовки на основании исходных материалов, а не
дополнительные ответы пользователя. Их можно уточнять в T01/T02, сохраняя R01–R16.
