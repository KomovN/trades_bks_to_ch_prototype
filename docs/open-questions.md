# Неопределённости и проверки перед выпуском

Основные вопросы организации согласованы; они перечислены в [решениях](decisions.md).
Следующие пункты не мешают подготовке и offline-реализации.

| ID | Что неизвестно | Кто и когда проверяет | Влияние |
| --- | --- | --- | --- |
| Q01 | Версия/архитектура production CH и действующая схема таблицы | T08/T09, получить `SELECT version(), timezone()` и `SHOW CREATE TABLE` перед rollout | Нет подтверждённой совместимости до проверки |
| Q02 | Текущий live wire format LastTradesSuccess, ack и error, включая пустой/не-object error | T01 фиксирует offline baseline, T09 собирает безопасные captures | Не выдавать synthetic fixture за запись сети; при несовпадении обновить fixtures и parser вместе |
| Q03 | Ограничения БКС по 101 инструменту на соединение и совместной работе с quotes | T09 при live smoke, по явным ошибкам/подтверждениям API | Не обещать полное покрытие подписки до проверки; не уменьшать список автоматически |
| Q04 | Refresh token rotation/одновременное использование токена сервисами | T04 оставляет существующий режим, T09 проверяет реальную политику без печати секретов | При требовании rotation нужно отдельное решение |
| Q05 | Реальная скорость ленты, RAM VM, доступный диск CH | T08/T09, короткий измеряемый soak | Defaults не являются throughput SLO |
| Q06 | Production host/database/user/TLS и способ доставки секретов | Перед реальным deployment в окружении сервера | Не запрашивать пароли в чате; не придумывать доступ |
| Q07 | Редкие trade-shaped сообщения с неполным side/price/quantity | T01 фиксирует такие frames как `malformed_trade`, T09 сверяет captures | Текущий baseline отклоняет sparse payload; изменение требует fixture и обновления протокола |

Для Q01–Q07 фиксируются факт проверки и результат; отсутствие доступа обозначается
`not run`, а не `passed`. Поручение на Harness не является поручением подключиться
к серверу или изменить production. Отдельного подтверждения каждой рутинной offline
задачи внутри будущего поручения на реализацию не требуется.

## Состояние после T09

S01–S16 приняты offline, включая настоящий локальный ClickHouse `24.8.4.13` и
container smoke с fake WebSocket. Эти результаты не закрывают ни один live/production
вопрос таблицы выше: Q01–Q07 остаются открытыми, S17 — `not run`,
**production readiness: unverified**. Quotes-сервис и production ClickHouse в ходе
приёмки не изменялись и не запускались.
