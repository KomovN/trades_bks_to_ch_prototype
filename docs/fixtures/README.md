# Fixtures и происхождение

[messages.json](messages.json) — синтетические примеры, составленные для контракта
и будущих tests. Это **не** сохранённые сообщения реального соединения.
`LastTrades` основан на README и подтверждении пользователя, вариант LastTradesSuccess
с payload — гипотеза совместимости с PDF. Поле `raw` — строка входной frame;
её нельзя получить через повторную сериализацию разобранного объекта.
`received_at` задаётся тестом отдельно. `expected_kind` — результат классификации,
`expected_event_time` — нормализованный UTC ISO timestamp, если применим.
Невалидные бинарные данные задаются `input_hex`.

Fixtures дополнительно закрепляют precedence: заполненный `error` всегда побеждает
trade-shaped payload, пустой object `error` не перехватывает дальнейшую классификацию,
а неизвестные поля без `side`/`price`/`quantity` не превращают ack/control в сделку.
Полная ручная трассировка cases приведена в таблице протокола. Все варианты остаются
синтетическими; только форма LastTrades подтверждена пользователем как реально рабочая.

[subscription-baseline.json](subscription-baseline.json) содержит provenance/hash
полного списка quotes, количество и hash упорядоченных `ticker|classCode\n` пар.
Это snapshot для воспроизводимости; `make check` не требует соседнего репозитория.
Новый список обновляется явно по поручению пользователя вместе со snapshot и решениями.
Runtime YAML loader в T02 использует PyYAML; упрощённый parser Harness проверяет
только принятую форму example YAML и не является библиотекой приложения.

[schema-baseline.json](schema-baseline.json) закрепляет hash пользовательского DDL
после свёртки whitespace. Изменения форматирования допустимы; изменение SQL требует
нового согласованного решения и обновления baseline.
