# T09 — Независимая приёмка и передача

## Цель

Оценить итоговый сервис по фактическим требованиям и подтвердить границы его готовности.

## Входные документы

- [Требования](../docs/specs/service.md), [приёмка](../docs/acceptance.md).
- [План](../PLANS.md), [реестр](index.json), [журнал](../docs/execution-log.md).
- [Runbook](../docs/operations.md), [вопросы](../docs/open-questions.md).

## Файлы

`tasks/reports/T09.md`, `docs/execution-log.md`, `docs/open-questions.md`, финальные
уточнения README. Найденные ошибки оформить адресно для владельца модуля;
не менять scope и DDL для получения зелёных тестов.

## Требования

R01–R16. Проверить трассировку всех требований и результаты S01–S16. Просмотреть
diff и фактический runtime, а не только отчёты исполнителей. Обязательно проверить
ненулевой выход при fatal error, bounded shutdown, raw fidelity и все 101 пары.

## Приёмка

- `make verify` проходит, ни один обязательный suite не пустой и не skipped без причины.
- Результаты команд, версии и not run зафиксированы. Существенные дефекты исправлены
  соответствующими задачами с повторной проверкой.
- Краткий итог отличает offline MVP от production/live readiness.
- S17 — отдельный этап по поручению пользователя с секретами из окружения.
  При отсутствии доступа report говорит `production readiness: unverified`.
- Нет изменений/запуска quotes-сервиса и production CH в ходе offline-приёмки.

## Проверки

`make verify`; проверка diff/образа/runbook; поиск утечек с тестовыми sentinel values.
S17 нельзя заявить пройденным по fake WS. Offline-задача может завершиться с этим
явно указанным ограничением; фактический production rollout — отдельное поручение.
