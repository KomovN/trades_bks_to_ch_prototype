# T07 — Supervisor, сигналы и наблюдаемость

Дата: 2026-10-17. Owner: `/root/t07_lifecycle`.

## Результат

- Реализован composition root `app/main.py`: загрузка settings/подписки, создание
  token provider, bounded queue, reader и writer без DI framework и скрытого runtime DDL.
- Supervisor наблюдает reader, writer и SIGTERM/SIGINT. Первый stop публикует один
  абсолютный monotonic deadline; reader прекращает producer, устанавливает
  `ProducerCompletion.done`, после чего writer дописывает принятые строки.
- Одновременное завершение workers разбирается без потери fatal-причины. Падение
  writer останавливает reader; падение reader останавливает intake, но уже принятые
  строки всё равно проходят bounded drain.
- По истечении deadline reader cleanup и отмена writer выполняются параллельно.
  Writer при отмене ожидает завершение bounded sync I/O thread, поэтому процесс не
  оставляет INSERT после выхода coroutine.
- Permanent auth после drain даёт exit 1 и настраиваемую задержку; SIGTERM/SIGINT
  прерывает эту задержку. Сигнал даёт exit 0 только при `accepted == inserted` и
  отсутствии строки, потерянной в гонке `put/stop`; fatal/deadline/unsaved дают exit 1.
- Добавлен моментальный `WriterSnapshot` для наблюдаемости без доступа к payload.
  Периодический и финальный summary содержат агрегированные счётчики reader/writer,
  очередь, batch и unsaved; строки сделок и raw JSON не логируются.
- Root logging handler удаляет известные access/refresh/ClickHouse secrets, Bearer
  values и token fields, включая exception text сторонних библиотек. Supervisor
  логирует только безопасный класс ошибки, а не её неочищенное сообщение.

## Ограничения и следующий шаг

- Процессная проверка использует настоящий драйвер и реальный отказ TCP connect,
  но не настоящий сервер ClickHouse. Совместимость INSERT/DDL и timeout выбранной
  версии сервера должна быть подтверждена T08/S15.
- Live BKS и production ClickHouse не использовались. S17, wire acknowledgement и
  поведение реального auth остаются отдельной live-проверкой T09 с разрешением.
- На платформах, где event loop не поддерживает `add_signal_handler`, установка
  POSIX handlers пропускается; deployment-цель Docker/Linux и текущая macOS проверены.

## Исправление по независимой проверке T09

T09 обнаружила, что root level `DEBUG` пропускал DEBUG/INFO сообщения сетевых
библиотек. Такие сообщения могут содержать полный WS frame или HTTP headers; одной
редакции известных token patterns недостаточно для защиты `raw_json`.

- `configure_logging` теперь принудительно задаёт минимум `WARNING` пространствам
  `websockets`, `httpx`, `httpcore`, `clickhouse_connect` и `urllib3`, включая уже
  созданные дочерние logger-ы.
- На root handler добавлен независимый source-level filter. Он отбрасывает DEBUG/INFO
  этих библиотек, даже если дочерний logger позднее сам установит `DEBUG`.
- Уровень `app` остаётся равным `LOG_LEVEL`, поэтому прикладная диагностика DEBUG
  сохраняется. Redaction известных secrets, Bearer и token fields продолжает
  применяться к разрешённым WARNING/ERROR сообщениям.
- Новый regression test передаёт sentinel raw frame и Authorization header через
  все пять библиотечных namespaces: wire DEBUG полностью отсутствует в output,
  `app.lifecycle` DEBUG присутствует.
