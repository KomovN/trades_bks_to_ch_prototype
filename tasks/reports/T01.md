# T01 — отчёт о контракте и fixtures

Дата: 2026-10-17. Owner: `/root/t01_protocol`.

## Результат

- Уточнён детерминированный порядок классификации: декодирование/JSON object,
  заполненный `error`, `responseType`, наличие discriminator-ключей, metadata.
- Заполненный `error` имеет приоритет над полями сделки. Отсутствующий, `null` и
  пустой object `{}` позволяют продолжить классификацию; неожиданный непустой тип
  `error` консервативно остаётся `source_error` и не создаёт строку сделки.
- Discriminator-ключи зафиксированы как точное множество
  `{side, price, quantity}`: все три дают trade-shaped payload, часть набора —
  `malformed_trade`, ни одного — `control`. `volume` и неизвестные поля решения
  не меняют.
- Добавлена offline-таблица решений, которая даёт ровно один kind всем 17 fixtures.
- Добавлены пограничные fixtures `control_with_unknown_fields`,
  `empty_error_object_trade`, `non_object_source_error`.
- Происхождение `LastTradesSuccess` по-прежнему явно synthetic. Реально рабочая
  форма `LastTrades` основана на подтверждении пользователя; список подписки берётся
  из quotes snapshot и этой задачей не менялся.

Изменённые файлы:

- `docs/fixtures/README.md`

ошибки, оба допустимых responseType, ack/control, partial payload, чужой тип,
невалидные JSON/root/UTF-8 и правила metadata/timezone.

- `jq -e . docs/fixtures/messages.json` — exit 0; JSON корректен.
- Проверка jq provenance, количества 17, уникальности имён и ровно одного из
  `raw`/`input_hex` — exit 0, результат `true`.

Runtime tests S02/S05/S11 этой contract-задачей не подменялись: они должны быть
реализованы в T02/T03/T06. Live БКС, Docker и ClickHouse не запускались.
