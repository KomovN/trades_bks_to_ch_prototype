# T06 — WebSocket reader и reconnect

Дата: 2026-10-17. Owner: `/root/t06_reader`.

## Результат

- Реализован `WebSocketReader`: один WS на полный JSON подписки из 101 инструмента,
  повторная подписка после reconnect и явные лимиты клиента `max_size=1 MiB`,
  `max_queue=16`.
- `received_at` фиксируется UTC wall clock непосредственно после завершения `recv()`,
  до следующей await-точки. Исходный frame передаётся parser без сериализации и
  только `trade` попадает в ограниченную `asyncio.Queue`.
- Получение frame, плановый timer по `AccessTokenProvider.ttl()` и stop ожидаются
  конкурентно. TTL завершает текущую сессию и вызывает повторную подписку даже при
  живом сокете и непрерывном потоке.
- Retry использует exponential backoff с bounded jitter и прерываемым ожиданием.
  Счётчик backoff сбрасывается только после сессии не короче 30 секунд; handshake
  сам по себе сбросом не считается.
- Handshake 401/403, structured source error 401/403 и auth close отделены от
  обычного disconnect. Static token завершается сразу; refresh token инвалидируется
  и принудительно получается один раз, повторный auth rejection до устойчивой
  сессии становится `PermanentAuthError`.
- Structured NoData (`error.code=1`) остаётся в той же сессии. NotFound и
  IncorrectJson (`2`/`3`) дают `PermanentSubscriptionError`; undefined/unknown
  source error идёт в bounded reconnect. Raw payload и тексты сторонних исключений
  не попадают в сообщения reader-а.
- Добавлены проверяемые `ReaderStats` и fatal-классы для supervisor-а T07.

## Producer completion API для T07

T07 создаёт один `ProducerCompletion` и передаёт его reader-у. `reader.run(stop)`
всегда устанавливает `completion.done` в `finally`, только после того, как reader
больше не может вызвать `queue.put`. При stop во время заполненной очереди сделка
записывается в `completion.unsaved_rows`; если `queue.put` и stop завершились в один
tick, владельцем считается очередь и растёт `accepted_trades`. Поэтому writer может
drain до условия `completion.done.is_set()` и отсутствия принятых элементов, не
делая вывод только из временного `queue.empty()`.

Публичные элементы интеграции:

```python
completion = ProducerCompletion()
reader = WebSocketReader(
    url=settings.ws_url,
    source=settings.source,
    subscription=subscription,
    token_provider=token_provider,
    queue=queue,
    completion=completion,
    reconnect_min_delay_sec=settings.reconnect_min_delay_sec,
    reconnect_max_delay_sec=settings.reconnect_max_delay_sec,
)
await reader.run(stop_event)
```

Fatal outcomes: `PermanentAuthError`, `PermanentSubscriptionError` и
`ReaderConfigurationError`. Остальные непредвиденные ошибки намеренно выходят из
worker task и должны быть замечены supervisor-ом.

## Ограничения и риски

- Live БКС не вызывался: реальные handshake headers, close codes, wire ack/error,
  лимит подписки и совместная работа с quotes остаются S17/Q02/Q03/Q07.
- Auth close codes основаны на стандартном policy-violation и распространённых
  application codes; фактический код БКС нужно зафиксировать safe capture в T09 и
  синхронно обновить контракт/тесты при расхождении.
- In-memory queue сохраняет согласованные ограничения: disconnect, crash или
  исчерпание shutdown deadline могут потерять сделки; replay отсутствует.
- T07 должен связать `completion.done`, состояние writer-а и единый shutdown
  deadline, а также вывести агрегированные счётчики без raw frames и токенов.
